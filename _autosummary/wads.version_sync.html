wads.version_sync¶

One version number for a Python package and its npm twin (i2mint/wads#210).

A repo that publishes the same code to PyPI and npm lists, in pyproject.toml, the manifests that carry the Python version too:

[tool.wads.ci.version]
sync = ["ts/package.json"]

Two things follow, both in uv-ci:

  • Release: right after the publish job bumps [project].version, it writes that version into each listed manifest (and the package-lock.json beside it), so the bump commit carries all of them.

  • Check: the setup job fails when a listed manifest’s version differs from [project].version, so a hand edit on one side shows up before a release.

And one in npm-ci: npm packs the commit that was pushed, which comes before the bump commit of the Python release the same push cuts, so it would carry the previous release’s number with newer code. npm_publish_refusal() refuses that publish (see its docstring).

Only package.json is supported: a Rust crate usually keeps its own version line. This module imports only the standard library (and wads.ci_config, which does too), because the CI scripts load it by path from the wads checkout (wads/scripts/_checkout_import.py).

wads.version_sync.npm_publish_refusal(pyproject_data, package_dir, changed_files, subject, *, also_inside=())[source]¶

Why npm-ci must not publish package_dir from this push, or None when it may.

It refuses only when all of these hold:

  • [tool.wads.ci.version].sync lists a manifest inside package_dir (so its version comes from the Python release);

  • this push also cuts a PyPI release (pypi_release_expected()), whose bump commit comes after the commit npm packs;

  • the push changes files outside package_dir (changed_files, repo relative). A push that changes only the npm package publishes the version the last Python release wrote. When the npm package is the repo root, every change counts as outside it. Files in also_inside (the npm stub’s own workflow file, which the Python stub’s paths filter ignores) count as inside.

>>> data = {"project": {"version": "1.2.3"},
...         "tool": {"wads": {"ci": {"version": {"sync": ["ts/package.json"]}}}}}
>>> npm_publish_refusal(data, "ts", ["ts/src/a.ts"], "Release [publish-npm]") is None
True
>>> print(npm_publish_refusal(data, "ts", ["ts/src/a.ts", "pkg/b.py"], "Release [publish-npm]"))
This push also releases the Python package, so npm would get the previous release's number (1.2.3) with newer code: uv-ci writes the new number into ts/package.json in its bump commit, after this one. Publish npm from a commit that changes only ts/ (or carries the skip-publish marker '[skip publish]'). Changed outside ts/: pkg/b.py
>>> npm_publish_refusal(data, "ts", ["pkg/b.py"], "Release [publish-npm] [skip publish]") is None
True
>>> npm_publish_refusal({}, "ts", ["pkg/b.py"], "Release [publish-npm]") is None
True
Return type:

str | None

wads.version_sync.pypi_release_expected(pyproject_data, subject)[source]¶

Whether uv-ci’s publish job releases to PyPI for a push with this commit subject.

Mirrors uv-ci’s gates (markers match the subject case-insensitively, like GitHub’s contains()): the skip-ci and skip-publish markers suppress the release; with [tool.wads.ci.publish].enabled = false only the publish marker cuts one; in on-demand trigger mode only the deploy marker does, or the run-ci marker when run_ci_publishes is on.

>>> pypi_release_expected({}, "Fix a typo")
True
>>> pypi_release_expected({}, "Fix a typo [Skip Publish]")
False
>>> off = {"tool": {"wads": {"ci": {"publish": {"enabled": False}}}}}
>>> pypi_release_expected(off, "Fix a typo"), pypi_release_expected(off, "Fix [publish]")
(False, True)
Return type:

bool

wads.version_sync.set_json_version(path, version)[source]¶

Write version into one package.json or package-lock.json, as npm would.

A lockfile carries the version twice: at the top and on its root package (packages[""]); dependencies’ versions are left alone. Everything else in the file, and its layout, is kept. Used by the release (set_manifest_version()) and by the git-commit action’s push-back conflict resolver.

Return type:

None

wads.version_sync.set_manifest_version(manifest, version)[source]¶

Write version into manifest and the npm lockfile beside it.

Returns the files written. Refuses a version npm would reject, before writing.

>>> import tempfile
>>> d = Path(tempfile.mkdtemp())
>>> _ = (d / "package.json").write_text('{\n  "name": "x",\n  "version": "0.0.1"\n}\n')
>>> [p.name for p in set_manifest_version(d / "package.json", "0.0.2")]
['package.json']
>>> print((d / "package.json").read_text(), end="")
{
  "name": "x",
  "version": "0.0.2"
}
Return type:

list[Path]
