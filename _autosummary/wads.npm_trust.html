wads.npm_trust¶

wads npm-trust: find a repo’s npm publishers and attach Trusted Publishers.

npm trusted publishing (OIDC, see the npm-publishing skill) needs, per package, one npm trust github <pkg> --file <caller workflow> --repo <owner>/<repo> [--env E] --allow-publish -y (npm >= 11.15, an owner login with 2FA) and the package must already exist on npm. Doing that by hand across a fleet means finding, for every package, the workflow that publishes it. This module does the finding, reports it, and optionally runs the commands:

  1. Discover (discover()): the workflows under .github/workflows that publish (npm publish, pnpm publish, pnpm -r publish, changeset publish, changesets/action with a publish: command, a script such as pnpm release that runs one of those, or a caller of a wads npm-ci*.yml reusable workflow), and the non-private packages each publishes (the package in the working directory, every workspace member for -r / --workspaces / changesets, or the --filter``ed ones), with the job's ``environment. A --dry-run, a commented or echo``ed line, or ``npm run publish:docs is not a publish. For a reusable workflow npm checks the caller’s filename, which is the file found here.

  2. Report (npm_trust(), the default): one row per (package, workflow, environment), saying whether the package is on npm or needs a first manual publish; a row whose name or environment cannot be resolved (${{ ... }}) or is unsafe to pass to npm says so and is never run.

  3. Apply (apply=True): run npm trust github for each package that is on npm, continue past per-package failures, and verify with npm trust list.

Everything that touches the world (npm, git) goes through one injectable run callable, so the discovery and the plan are testable without a network.

>>> trust_command(Publisher("@x/a", "o/r", "release.yml", "npm"))
['npm', 'trust', 'github', '@x/a', '--file', 'release.yml', '--repo', 'o/r', '--env', 'npm', '--allow-publish', '-y']

Bases: object

The flags of one package manager that change what a publish call covers.

Each manager reads the same spelling differently (pnpm’s -w is the workspace root and takes no value, npm’s -w names a member and takes one), so the flags are per manager, never shared sets. Only filter and directory flags take a value; every other flag is read as a switch.

Whether an npm trust list text has an entry naming exactly this repo and workflow.

Whole tokens only, so o/rr or release.yml.bak never stand in for o/r or release.yml.

wads.npm_trust.npm_trust(repo='.', *, apply=False, dry_run=False, github_repo=None, offline=False, fmt='table')[source]¶

Find the npm packages repo publishes and attach Trusted Publishers (dry run by default).

Prints one row per (package, workflow, environment) with whether the package is on npm or needs a first manual publish, and the npm trust github call for each package --apply would act on. Nothing changes unless --apply (--dry-run is the explicit spelling of the default): then each package that is on npm gets its Trusted Publisher (needs npm >= 11.15 and an owner login with 2FA), failures are reported per package, and every attach is verified with npm trust list. --offline skips the npm lookups; --github-repo owner/name overrides the origin remote.

wads.npm_trust.packages_of(root, call)[source]¶

Names of the non-private packages call publishes in the repo at root.

Filters, -r and -w are evaluated from the workspace root above call.directory (as the package managers do), not from call.directory.

wads.npm_trust.select(items, patterns, matches, *, default_all)[source]¶

Items picked by patterns, where a ! prefix subtracts its matches.

With no inclusive pattern the result is every item (default_all) or none, minus the exclusions: pnpm --filter '!b' means “all but b”, a workspace list of only !x globs means “no members”.

>>> select("abc", ["a", "!b"], str.__eq__, default_all=True)
['a']
>>> select("abc", ["!b"], str.__eq__, default_all=True)
['a', 'c']
>>> select("abc", ["!b"], str.__eq__, default_all=False)
[]
